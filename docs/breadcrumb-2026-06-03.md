## Conjecture 1 — Retrospective analysis dissolves two of the four spine breaks

**The turn (Tony's, paraphrased):** We spent the whole conversation on
*prospective* analysis — look at prompt `p`, decide if it's incoherent *before*
the model runs. That is exactly where the spine broke (oracle is
context-blind; needs operating context O it can't see from inside the prompt).
But Indaleko's judge was clear and *retrospective*: "this AQL did not run."
Combine the two: given a discordant output and the prompt that produced it, can
we attribute which input fragment caused the discord?

**Why it's strong (flagged as conjecture, verify before building):**
- "This AQL did not run" is **ground truth**, not an oracle judgment. The hard
  prospective question ("is this *really* a conflict?") is answered for free by
  the failure itself. You ask the easier question: "it failed — what made it so?"
- It repairs **spine-break #2** (impossibility dodge): prospectively the oracle
  had to *predict* failure without observing O, which relocated the impossibility
  into the human labeler. Retrospectively, **O is observed, not predicted** — the
  query ran in a real context and you watched it fail. The failure IS the
  measurement of O.
- It repairs **spine-break #3** (frame-relative blind spot): retrospection
  doesn't need to *recognize the conflict class in advance*. It only needs the
  output to be discordant, then traces back. The blind spot was a property of
  prospective recognition; retrospection doesn't have it.
- **The mechanism is ablation.** Tony's headwater fix ("I removed the conflicting
  instruction and the error dissipated") IS the algorithm: take the prompt that
  failed, ablate fragments (or pairs — conflicts often live in a pair, cf.
  Record.Attributes), re-run against the SAME context O, and the fragment whose
  removal makes the failure dissipate is the culprit. It is `git bisect` for
  prompt incoherence. The blueprint's Thread 4b "anti-truth set / ablation
  methodology" is the existing instrument.
- **The loop:** each confirmed retrospective case is a labeled example
  `(prompt, context, culprit-fragments, failure)` — which is exactly the
  ground-truth C the skeptic said the prospective oracle was missing, EXCEPT
  generated by observation, not by a fallible human labeler. Retrospective
  analysis manufactures the training data the prospective oracle couldn't
  honestly get. ε then becomes well-defined: the false-negative rate of the
  prospective flag *measured against retrospectively-confirmed ground truth.*
- **This is the executor/observer split resolved across TIME, not across agents.**
  You don't need a second model as observer. You need the same system, after the
  fact, with the failure in hand. Time gives you the observer for free.

**The honest bound (do not lose this):** retrospective analysis is powerful
exactly to the degree the failure is **loud**. "AQL did not run" is a beautiful
oracle (binary, external). `mandatory_features` is loud (R² collapse, measurable).
The dangerous cases are the QUIET ones — output is plausible but wrong, nobody
notices — and there you're back to the epistemic-honesty problem (needing someone
to notice the output was bad). So the method's reach is bounded by
failure-audibility. That bound is itself probably a useful axis (see Conjecture 2).

## Conjecture 2 — ε is unboundable over natural language; the research is the trade-off curve

**The turn (Tony's):** Maybe the ontology work teaches us that the ε band is
never good in the general case — and that's a *finding*, not a failure. Which
points at DSLs (already discussed for system prompts): we *can* achieve bounded ε
with a restricted language, so we know it's possible; then study what restricting
the permissible prompt language buys.

**The reframe (flagged as conjecture):**
- Natural language is the maximally permissive prompt language. Every audit break
  (weld, unbound term, frame-relative blind spot, context-dependence) is a
  consequence of NL permitting loose / implicit / frame-relative binding. ε is
  large in the general case because the *grammar* is too loose to check — the
  drift is *legal* in NL.
- So stop trying to make ε small over a fixed (natural) language. Ask: **what
  language makes ε bounded?** Answer: a restricted one. A DSL with typed
  primitives (mandate/prohibition/scope/precedence — Arbiter Thread 3a, blueprint
  ~lines 265–279) *forces* first-class binding; the weld this instance committed
  would be a **syntax error** in that language. The DSL is the **existence proof**
  that bounded ε is achievable — nearly definitional, not something to argue.
- This converts ε from a quality metric into an **expressiveness–coherence
  trade-off**: NL = max expressiveness, ε unbounded; strict DSL = min
  expressiveness, ε near zero; everything between is a curve. **The research is
  the curve** — "what does ε(expressiveness) look like, where are its knees?" —
  not "what's our ε."
- Possible **limit theorem**, same family as the epistemic-honesty impossibility
  and the FLP analogy the program keeps rhyming with: *"You cannot have both
  unrestricted prompt language and bounded incoherence."* DSL = the constructive
  escape. The curve = the price list (what coherence costs in expressiveness).

**Tony's "dubious" probe — keep it, it's not dubious:** "you can only use
Indonesian for system prompts — does that restrict us enough to fit the ε band?"
This tests a DIFFERENT axis than the DSL. DSL restricts the *grammar* (what
bindings are expressible). Language-restriction restricts the *register* — and
Paper 3 says register changes the *social processing* of obligation independent
of semantics. So:
- DSL-only may kill **binding-conflict** (syntactic) incoherence.
- Language/register restriction may kill **frame-relative** (pragmatic)
  incoherence — the exact class the structural oracle was blind to (spine-break
  #3). Indonesian's obligation-marking is plausibly the opposite end from the
  Spanish that *inverted* topology in Paper 3.
- **CONJECTURE, unverified:** these two restrictions attack the two different
  incoherence types the audit separated. A DSL is still rendered in *some* NL's
  terms, so it may not fix frame-relative incoherence on its own.

## The open question both conjectures depend on

**Are the incoherence axes one axis or three?** Binding-conflict (Indaleko,
syntactic) / granularity (FNMA case #11) / frame-relative (Paper 3 register).
The "three witnesses = one law" claim was downgraded in `spine-audit.md` to "three
cases worth testing for isomorphism" — NOT proven isomorphic. Building the
ontology of incoherence-types is how you'd settle it. If they're one axis, there's
a law and a single ε; if three, ε must be stratified by type. Everything
downstream (is it a law / can a DSL alone bound ε / does Indonesian-only buy
anything) depends on this answer.
